# sieve-bench

## どのスタイライズドファクツが、シミュレーションを見破れるのか

**結論：最も報告される統計量は GARCH と分けられず、最も効く統計量は報告されていない。**

（「報告頻度が高いほど識別力が低い」という単調な関係を主張しているのではない。
文献289本で報告頻度と識別力の相関を取ったところ、集約の仕方次第で
−0.56 から +0.75 まで符号が振れた。主張はあくまで上の2つの名指しである。）

金融のエージェントベース・モデルや LLM シミュレーションの論文は、ほぼ必ず
「スタイライズドファクツを再現した」と書く。だがその再現が**何を証明しているか**は
測られてこなかった。ある統計量を再現できたことは、そのモデルが現実に近いことを
意味するのか。それとも、その統計量が誰にでも再現できるだけなのか。

ここではそれを直接測る。

## やり方

各統計量は、1本のリターン系列を1つの数に落とす。実データの窓を多数集めれば
その数の分布が出る。生成器の実行を多数集めれば、そちらの分布も出る。
**2つの分布がどれだけ重なるか**が、その統計量の識別力である。

重なりは **2標本 Kolmogorov-Smirnov 統計量**（分布関数の最大乖離）で測り、
p 値は **暦ブロックの復元抽出**で出す（後述）。

```bash
python3 fetch.py         # 指数データを取得（30秒）
python3 separation.py    # 本体（2分）  → separation.json
python3 selftest.py      # 検定そのものの検証（5分）
python3 robustness.py    # 頑健性の点検（1分）
python3 models/status.py # 実装の状態（1秒）
```

## v0.2 で直したこと

**v0.1 の p 値は無効だった。**そのほか、レビューを受けて7点直した。

### 1. 置換検定の交換可能性が破れていた（最優先で修正）

v0.1 は実データ 124 本と生成 200 本を1つのプールに入れ、**ラベルを完全に
ランダムに入れ替えて** p 値を出していた。これは 324 個が交換可能という仮定だが、
実データの窓は交換可能ではない：

- 窓長 1000・ストライド 250 なので、隣り合う窓は 75% を共有する
- 2008年や2020年の窓は6指数すべてに同時に現れる
- EURO STOXX 50 は DAX 構成銘柄を含むので一部は二重計上

`robustness.py` で実効標本数を出してはいたが、**それは区間の話であって、
p 値そのものは直していなかった。**

どれだけ壊れていたかを `selftest.py` で直接測った。実データと同じ形の依存を
持つ標本を、**同じ周辺分布**から作った独立標本と比べる。帰無仮説は真なので
棄却率は 5% であるべきである：

```
ブロック内相関      完全置換(v0.1)   ブロック置換   ブロック復元抽出
rho = 0.0               3.7%          4.7%          9.3%
rho = 0.3              36.0%         11.3%         10.0%
rho = 0.6              55.7%         12.7%         11.3%
```

**名目 5% に対して実際は 56%。**交換の単位を窓1本から暦ブロックに上げると
（`resampling.block_boot_test`）大きく改善する。

### 2. これは「補正法が無い」という話ではない

構造はこうである。

```
窓が 250 ずつ重なる                   →  系列方向の依存
同時期の6指数が共通ショックを受ける    →  横断方向の依存
                    ↓
        見かけの標本数 124 ≫ 独立な情報単位
                    ↓
   観測単位での置換が依存構造を壊す（交換可能性が成立しない）
                    ↓
            size が 5% → 56% に膨張
                    ↓
  依存を保つ推論は擬似反復を避けられる。**手法は存在する。**
                    ↓
   ただし独立な暦ブロックは6個しか残らない → 解像度も検出力も本質的に低い
```

**「どの手法でも直らない」は言い過ぎである。**暦ブロック単位の randomization
inference、block bootstrap、wild cluster bootstrap、HAC、モデルベースの推論など、
依存構造を保つ方法は存在する。本ベンチが測ったのはそのうち2つだけである。

消せないのは手法の側ではなく**情報量の側**である。25年を4年窓で見れば独立な暦は
6個しかなく、どの手法もそれ以上の情報を作れない。クラスタ数が 20 を切ると
過剰棄却するのは計量経済で広く知られている（Cameron, Gelbach & Miller 2008）。
平滑化で tie の副作用を消しても改善しないことは確認した。

つまり正確な結論は——
**補正法が無いのではなく、正しく補正すると、元々データに無かった独立情報の
欠如が露呈する。**

そこで名目の閾値を下げて較正した：

```
ブロック内相関     alpha=0.05   alpha=0.02   alpha=0.01   alpha=0.005
rho = 0.2            12.0%         5.2%         3.2%         2.2%
rho = 0.4            12.0%         6.6%         4.2%         1.8%
rho = 0.6            10.6%         5.2%         4.8%         3.0%
```

**名目 p < 0.01 で真の大きさが 3〜5% に収まる。**以下の表の `*` はこの線である。

**この較正には代償がある。**同じ `selftest.py` で測ると、判定線 p < 0.01 での
検出力は、平均が 0.5σ ずれた相手で 32%、標準偏差が 1.5 倍ずれた相手で **8.7%** しかない。
**分離が出ないことは、統計量が鈍い証拠にならない。**逆に、下の表で p が小さい行は
それだけ大きな差だということである。

### 2b. 露呈のしかた —— p 値の解像度

実データ同士の対照では、両側が**同じ暦ブロックを共有している。**2008年の米欧と
2008年のアジアは同じショックを受けているので、独立な単位ではない。
v0.2 の途中まではこれを対応なしのブロック置換で検定していた。設計として誤りである
（帰無分布が広くなる方向なので保守側ではあった）。

正しくは**ブロックごとに群ラベルを入れ替える**（`resampling.paired_block_test`）。
そして、そうすると割り当ては **2^6 = 64 通りしかない。**64通りを全列挙して
p 値を出している。

```
対照            設計              割り当て   p の刻み   実際の最小 p
region          paired_block         64通り    0.016      0.031
era             unpaired_block       35通り    0.029      0.030
gspc_vs_ftse    paired_block         64通り    0.016      0.156
gspc_split      paired_block         64通り    0.016      0.125
```

**どの対照も、上で決めた判定線 p < 0.01 に構造上到達できない。**
検定の欠陥ではない。独立な暦が6つしか無いという事実が、そのまま p 値の
刻みとして表に出ている。5% 水準で精密な推論をする設計として、
**このデータはもともと解像度が足りない。**

### 3. 「天井」という呼び方をやめた

v0.1 は米欧 vs アジアの KS を「天井」と呼んでいた。これは行き過ぎだった。
取引制度・通貨・産業構成・期間が違う2群の差より生成器との差が小さいからといって、
その生成器が対象市場を再現している証拠にはならない。

**参照対照**（現実どうしのばらつきの一例）と呼び直し、参照を4つに増やした。
同じ市場の別時代、最も似た2市場、同一市場・同一時代の分割まで並べる。

### 4. 周辺分布を16個並べるだけでは足りない

個別の KS を16回やると、どれも個別には合っているのに同時分布が現実と全く違う
生成器を通してしまう。統計量ベクトル全体の **energy 検定**を足した（総合層）。
個別の KS は「何が壊れているか」の診断として残す（総合スコアだけでは説明できない）。

### 5. 多重性

16統計量 × 8生成器 = 128 セル。Benjamini-Hochberg の q 値を出す。

ただし「**この統計量は全生成器を落とせる**」という主張には補正は要らない。
全部が有意であることを要求する側は交差-合併検定であり、もともと水準を超えない。
補正が要るのは「どこかに有意差がある」を探す側だけである。

### 6. 梯子に非対称なボラティリティ・モデルが1つも無かった

v0.1 の結論は「効いたのは `leverage` だけだった」。だが `garch_norm` / `garch_t` は
どちらも**対称な**モデルである。対称なモデルが非対称性の指標で落ちるのは
ほとんど定義から従う。**非対称なモデルが梯子に無い状態では、何も試されていない。**

GJR-GARCH と EGARCH を足した。**この2つは `leverage` を選んだ後に足したので、
v0.1 の統計量選択に対して純粋に held-out である。**選択用と評価用の分離が、
ここで初めて1つだけ実現している。

同時に `garch_t` の推定を直した。v0.1 は**正規尤度で当てた**パラメータに後から
t 分布のイノベーションを載せていた。ここでは (ω, α, β, ν) を同時に最尤推定する。

### 7. `gain_loss_asymmetry` は歪度だった

v0.1 の `gain_loss_asymmetry` は標準化3次モーメント、つまりただの歪度である。
金融でいう gain/loss asymmetry は通常、利得側と損失側の**到達時間**の非対称
（Jensen, Johansen & Simonsen 2003 の inverse statistics）を指す。名前が実装を
誤って表していた。

- 旧実装 → `return_skewness` に改名（値は変わらない）
- `gain_loss_asymmetry` → 到達時間版として新規に実装

新しいほうは実データで中央値 +0.42（上げは下げより 52% 長くかかる）、
ガウス生成器で −0.12 とほぼ 0 になる。文献の記述どおりに振る舞う。

### 8. 実装の verification と validation を分けた

`models/status.py` に、モデルごとの状態を機械可読で持たせた。

```
                            franke_westerhoff       chiarella_iori
specification_conformance            verified              partial
invariant_tests                          pass                 pass
paper_replication                        pass                 fail
empirical_validation                     fail              not_run
```

上3行が verification（論文どおりに動くか）、最終行だけが validation（現実と合うか）。
**Franke-Westerhoff は論文 Table 2 を8つとも再現するのに、実データとの照合では
落ちる。**この2つは別の問いである。不変量は宣言ではなく実際に走らせて確かめる
（Chiarella-Iori の株式・現金の保存は相対誤差 0.0）。

## 生成器の梯子

比較対象には、正解が分かっている生成器を並べる。目的は落とすことではなく、
**落とせないことを見つけること**にある。

| 生成器 | 何を持っているか |
|---|---|
| `gaussian` | 何も持っていない。ここで分けられない統計量は使い物にならない |
| `student_t` | 重い裾。時間構造なし |
| `iid_bootstrap` | 実データの値そのもの。時間構造だけが無い |
| `block_bootstrap` | 短期の時間構造のみ（ブロック長20） |
| `garch_norm` | **対称な**クラスタリング |
| `garch_t` | 対称なクラスタリング＋重い裾（同時最尤推定） |
| `gjr_t` | **非対称な**クラスタリング＋重い裾 **（held-out）** |
| `egarch_t` | 非対称（対数分散・指数型） **（held-out）** |

推定値（S&P500、`baselines.json`）:
GARCH-t (ω,α,β,ν) = (0.011, 0.118, 0.875, 6.47)、
GJR-t (ω,α,γ,β,ν) = (0.015, 0.000, 0.223, 0.876, 7.14)、
EGARCH-t (ω,α,γ,β,ν) = (−0.010, 0.146, −0.169, 0.974, 6.97)。
GJR の γ = 0.223 に対し α = 0、EGARCH の γ = −0.169。**どちらも実データどおりの
強い非対称性を持っている。**

`iid_bootstrap` は時間構造だけを壊す。ただし **周辺分布が一致するのはプール全体に
対してであって、個々の窓（単一指数・単一時期）に対してではない。**

生成器は各200回。全統計量はスケール不変。

energy 検定は**8生成器すべてを落とす**（p ≤ 0.0025）。GJR-t（E=66）と
EGARCH-t（E=58）も含む。個別の周辺分布では素通りする生成器でも、
**16個の同時分布としては現実と違う。**

### 参照対照 —— 現実どうしでもどれだけ違うか

**天井ではない。**現実の側の変動が、どのくらいの大きさなのかの目安である。

**KS の大きさだけを比べること。p 値は対照どうしで比較できない**（実データ同士は
両側ともブロック構造を持つので帰無分布がずっと広い。標本数も違う）。

## 読み取れること

**1. ボラティリティ・クラスタリングの再現は、機構については何も言わない。**

`acf_abs_1` は ABM 論文が最も頻繁に載せる統計量だが、`garch_norm` に対する KS は
**0.12（p = 0.38）**で分けられない。`block_bootstrap` に対しても 0.16 で分けられない。

ここは v0.1 より正確に書き直す。v0.1 は「ほとんど何も証明していない」と書いていたが、
言い過ぎだった。正確には：

> ボラティリティ・クラスタリングの再現は、現象論的な妥当性の一部を示す。
> だが、**それがエージェント相互作用によって生じたことの証拠にはならない。**

クラスタリングを出せること自体は確認できている。示されていないのは、その原因が
モデルの機構であることのほうである。GARCH(1,1) と区別がつかない以上、
その主張は識別されていない。

**2. 合わせ込んだ量では判定できない。**

`ljung_box_sq` は `gaussian` / `student_t` / `iid_bootstrap` に対して 0.98〜0.99 と
ほぼ完璧に働くのに、`garch_norm` に対しては **0.13** に落ちる。GARCH はまさに
この構造に合わせて作られたモデルだからである。

**これは分子動力学の力場検証と同じ話である。**密度に合わせ込んだ力場を密度で
評価しても何も分からない。判定は**合わせ込んでいない量**でやらなければならない。

**3. `leverage` は held-out でも生き残った。ただし差は縮む。**

判定線 p < 0.01 で**全8生成器**を落とせたのは `leverage` だけである（最悪 p = 0.005）。
非対称ボラティリティ・モデルを足せば落ちるだろうと予想していたが、落ちなかった。

**だが余裕は大きく削れている。**

```
garch_norm  0.93   →  gjr_t  0.53   →  egarch_t  0.33
```

そして **`egarch_t` に対する 0.33 は、米欧 vs アジアの 0.32 とほぼ同じ大きさ**である。
統計的には有意でも、**差の大きさは実市場どうしの違いと同程度**まで来ている。
`block_bootstrap` に対する 0.33 も同じ水準である。

より正確な言い方は「`leverage` は生成器を見破る」ではなく、
**「`leverage` は対称なボラティリティ・モデルを大きな差で見破る。非対称モデルに
対しては、実市場間の異質性と同程度の差しか残らない」**である。

指数別に見るとさらに弱くなる。`gjr_t` に対する `leverage` は混合で 0.53 だが、
**ハンセンだけでは 0.29** である（`robustness.py`）。

**そして `leverage` は、ABM 論文でほとんど報告されない。**

**4. `excess_kurtosis` の v0.1 の値は、`garch_t` の推定ミスの産物だった。**

v0.1 は `excess_kurtosis` が `garch_t` を KS 0.72（p < 0.001）で落とすと報告していた。
同じ KS で測って、`garch_t` の推定だけを同時最尤に直すと **0.10（p = 0.73）で
全く落とせない。**v0.1 の `garch_t` は、正規尤度で当てた分散パラメータに
ν = 2.65 の裾を後付けした別物のモデルで、裾が合わないのは当たり前だった。

**基準線の推定を間違えると、統計量の識別力を過大評価する。**この表は生成器の
性能表ではなく統計量の性能表なので、**基準線が弱いと統計量が強く見える。**

**5. 単独で全てを捉える統計量は存在しない。**

生成器ごとに、判定線を越えた統計量はきれいに食い違う。

```
block_bootstrap  acf_abs_decay 0.76, acf_abs_20 0.73, leverage 0.33, variance_ratio_20 0.22
garch_norm       leverage 0.93, excess_kurtosis 0.64, aggregational_gaussianity 0.59, ...（11個）
gjr_t            return_skewness 0.56, leverage 0.53, acf_abs_decay 0.35, gain_loss_asymmetry 0.28
egarch_t         return_skewness 0.48, acf_abs_decay 0.34, leverage 0.33, variance_ratio_20 0.24
```

**互いに補い合っている。**`acf_abs_20` は `block_bootstrap` を 0.73 で捉えるが
`garch_norm` には 0.09 で無力。`leverage` は `garch_norm` を 0.93 で捉えるが
`block_bootstrap` には 0.33（全生成器中の最悪値）。ブロック・ブートストラップは
実データのリターンをブロックごと再利用するので、**実データを切り貼りした系列は
実データと同じレバレッジ効果を持つ。**当然ではあるが、この統計量が万能でないことの記録。

held-out の2つを捉えたのは4個ずつしかなく、最も効いたのは `return_skewness` である。
**非対称なボラティリティを持っていても、イノベーションが対称なら歪度で落ちる。**
そしてその `return_skewness` は `block_bootstrap` には 0.18 で無力である。

**バッテリーが要るという主張の根拠がここにある。**

**6. 「リターンは予測できない」は検証に使えない。**

`acf_return_1` は全生成器に対して 0.13〜0.35。誰でも再現できるので情報が無い。

**7. この表に出ない失敗の仕方がある。**

`variance_ratio_20` と `drift` はここに並べた8生成器に対して弱い。表だけ見れば
無用な統計量に見える。

だがこの2つは**後から足した**もので、足した理由は生成器ではなく **ABM** にある。
既存の ABM 実装を S&P500 に較正して通したところ、実データの3〜5倍も強く平均回帰し
（VR(20) が実データ 0.75 に対して 0.13〜0.31）、ドリフトは4〜10倍あった。
**元の13個はどれもこれを直接には見ていなかった。**

```
                drift(mean/σ)   実データ比
実データ窓124本      +0.0168        —
Chiarella-Iori     +0.0678      4.0倍
Franke-Westerhoff  +0.1587      9.5倍
Zero Intelligence  +0.1443      8.6倍
```

較正側の欠陥でもあった。較正の目標3つのうち尖度と `acf_return_1` はドリフトに
盲目なので、**最適化はドリフトを好きなだけ盛れた。**ドリフトを実データの95%範囲に
制約して較正し直すと、Chiarella-Iori の損失は **0.050 → 2.830** に悪化した。
**モデルは非現実的なドリフトを使って尖度とクラスタリングを作っていた。**

**8. 平均を、誰も見ていなかった。**

上の drift は、較正した ABM の累積リターンを100本重ねて描いたときに
**人間が図を見て気づいた。**当時の14個はどれも検出できなかった。

**これを「有限のバッテリーには必ず穴がある」という一般論にするのは、ごまかしである。**
見落としたのは**一次モーメント**で、珍しい汎関数ではない。系列の最も基本的な要約が
バッテリーに入っていなかった。以前ここには「バッテリーが網羅的でないことを
バッテリー自身は教えてくれない」と書いていたが、**設計ミスを認識論の問題に
すり替えていた。**この件についてそれは当たらない。

原因は走らせる前に分かるものだった。当時の14個は全てスケール不変に設計してあり、
うち6個は定義に平均の差し引きを含み、残り8個は `|r|` か自己相関を経由する。
**つまりバッテリー全体が、構造上、位置に対して不変だった。**

```
        ┌─ 平均を引く ────┐            6個
  r ────┤                  ├──→ 統計量        位置の情報はここで消える
        └─ |r| / 自己相関 ┘            8個

  r ────→ 平均 / σ  ←── どの経路にも乗っていない（ABM のドリフトはここに出ていた）
```

スケール不変にしたのは意図的である。**位置に対しても不変になっていたのは、
誰も数え上げなかっただけの副産物である。**一つ不変性を宣言すると、ついてくる
不変性がある。その一覧を作っていなかった。

**教訓は「網羅は原理的に難しい」ではない。自分のバッテリーが何に対して不変かを、
先に列挙すること。**不変群に入るものは定義上どうやっても見えない。これは実行前に
紙の上で確認できる。

そして**時間をかければ気づいた類のものではない。**同じ道具で測り続ける限り、
消えた情報は戻らない。気づいたのは、図という別の様式で見たからである。

### AUC 版について

v0.1 の初期は power = 2|AUC − 0.5| を使っていた。AUC は確率的順序、つまり
位置ずれしか見ないので、中心が同じで形が違う分布にほぼゼロを返す：

```
中央値同一・分散5倍差   power 0.138   KS p = 2.7e-13
二峰性 vs 単峰         power 0.003   KS p = 2.2e-17
```

さらに雑音床が測られていなかった（同一分布同士でも 124 対 200 なら平均 0.052）。
`run_power.py` と `power.json` に比較用として残してある。

## 統計量の選び方について（開示）

**`variance_ratio_20` と `drift` は、ABM の失敗を見てから足した。**そして同じ ABM に
対する分離度を報告している。これは選択的推論の問題であり、
**経緯を開示しても補正にはならない。**

v0.2 で一歩だけ進んだ。`gjr_t` と `egarch_t` は統計量を選び終えた後に足したので、
**この2列に対する数字は選択の影響を受けていない。**`leverage` が全生成器を
落としたという結論は、この held-out 2列を含んだうえでのものである。

ただしまだ足りない。次の版では最初から3つに分ける：

- **Discovery models** — 統計量を見つけるためだけに使う
- **Development models** — 実装の調整に使う
- **Hidden challenge models** — 最終評価だけに使い、開発中は見ない

なお `gain_loss_asymmetry`（到達時間版）は v0.2 で新規に足したが、これは
**名前と実装を一致させるため**であって、識別力を見てから足したものではない
（実装してから初めて数字を見た）。

**公開後には逆向きの同じ問題が起きる。**このベンチに合わせ込む（Goodhart 化）
動機が生じ、上の「読み取れること2」がベンチ自身に跳ね返る。

## 正直に書いておく限界

1. **LLM シミュレーションをまだ通していない。**今あるのは既知の生成器だけである。
   意味があるのは、公開されている LLM エージェント市場シミュレーションの
   出力を通した時点から。**これが本番。**
2. **独立な暦ブロックが6個しかない。**これが全ての精度を縛っている。
   検定は名目水準を達成できず（較正で対処）、検出力も低い（標準偏差1.5倍の
   ずれを 8.7% しか捉えられない）。実データ同士の対照では p の刻みが 0.016 になり、
   判定線に届かない。**これは推論手法の問題ではなく実験単位の不足**なので、
   統計手法では解けない。指数を増やすか、窓を短くするしかない
3. **実効標本数の v0.1 の推定は甘かった。**v0.1 は窓の通し番号 k を「同じ時期」の
   代理に使っていたが、営業日数が指数ごとに違い、EURO STOXX 50 は開始が5年半遅い。
   暦で測り直すと実効標本数の中央値は **48 → 23**（名目124に対し 5.5 倍の希釈）。
   v0.1 が書いていた「1.59倍に広げるべき」は過小だった
4. **ブロックの継ぎ目。**ストライド 250・窓長 1000 なので窓は数珠つなぎで、
   完全に独立なブロックには分けられない。区切りの直前と直後の窓は最大 99% を
   共有する。ブロック化はこの継ぎ目を許した近似である
5. **GARCH 系は S&P500 のみで推定**し、それを全指数の基準線として使っている
6. **`student_t` の自由度 2.65 について。**v0.1 はこれを「極値に引かれたバイアス」と
   書いていたが、正確には**無条件分布への iid-t の最尤推定値**である。同時最尤推定に
   よる**条件付き**イノベーションの自由度は 6.47（`garch_t`）で、こちらが通常
   報告される値。別の量を推定しているだけで、どちらも誤りではない
7. **日次のみ。**日中データを入れると、マイクロ構造由来の統計量が追加できる
8. **統計量は16個。**Cont (2001) の主要な事実は覆っているが、網羅ではない。
   14個目と15個目はどちらも ABM を通して初めて必要と分かったもので、
   **同じことがまだ他にも起きうる**
9. **`aggregational_gaussianity` が不安定。**データを 36,073 点から 36,079 点に
   変えた（各指数の先頭に1〜2日足しただけ）ところ、この統計量だけ大きく動いた。
   **現在の窓数では推定量の分散が大きすぎる**
10. **Hill の k を 5% に固定している。**k を 2.5%→10% と振ると実データの推定値が
    3.54→2.97、`garch_t` に対する KS が 0.14→0.27 に動く。
    **`hill_*` の行は k の選択に依存している**
11. **梯子はまだ失敗の仕方を網羅していない。**v0.2 で非対称ボラティリティを足したが、
    確率的ボラティリティ、レジーム・スイッチング、長期記憶（FIGARCH / HAR）、
    時系列 GAN は入っていない。構造を持つモデル（ABM や LLM エージェント）が
    起こす壊れ方も、`variance_ratio_20` と `drift` で見たとおり別枠である
12. **同等性検定になっていない。**現状は「差が有意か」を見ている。認証基盤にするなら、
    参照対照から許容幅を決めて**非劣性・同等性検定**にすべきである。まだやっていない

**1 が本番。2 が全体を縛っている。12 が次の設計課題。**

## 何のためにやっているか

生成的シミュレーションが企業や金融機関の意思決定に入り始めている一方で、
**その出力が現実と同じ形をしているかを、生成した側から独立に判定する手続きが
存在しない。**各社が自ら採点した妥当性スコアを公表している状態にある。

判定を作るには、まず**判定に使える統計量とそうでない統計量を分ける**必要がある。
この表はその最初の一枚である。

そしてこのリポジトリの本体は、16個の統計量そのものではなく、
**「観測量 × 欠陥機構」の識別行列**である。統計量 T_j と既知の欠陥を持つ生成器 M_k に
対して D_jk = separation(T_j(実データ), T_j(M_k)) を埋めていく。
上の表がその行列で、`selftest.py` はその測定装置自体の校正証明書にあたる。
