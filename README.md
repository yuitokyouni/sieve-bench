# sieve-bench

## 検証バッテリーそのものを監査する

**主張は2つ。どちらもシミュレーションで見つけたのではなく、測って出した量である。**

> **① 調査した論文の8割は、自分が主張している機構の「時間の向き」を検証できない
> 組み合わせを使っている。**これは解析的な事実で、データ量とは無関係に成り立つ。
>
> **② この分野の標準的な窓の切り方に標準的な置換検定を当てると、
> 帰無仮説が真でも 56% 棄却する**（名目 5%）。v0.1 の本ベンチ自身がそうだった。

どちらも「スタイライズドファクツによる検証は不十分だ」という話ではない。
**それは既に指摘されている**（Platt & Gebbie 2016）。本ベンチの寄与はそこではなく、
**不十分さの内訳を、検証可能な量として出したこと**にある。

### なぜ2つに絞ったか

「どの統計量に識別力があるか」を測った行列（下の方にある）もあるが、
**あれは先行研究に対して漸進的**である。上の2つは違う。

- ①は**シミュレーションを必要としない。**統計量の定義だけで決まる。
  だから他人の論文にそのまま適用できて、反証もできる
- ②は**測定値**である。「窓が重なると p 値が甘くなる」は常識だが、
  「この設計では 11 倍甘い」は誰も出していない

## ① 不変性監査 — 「原理的に見えない」を先に列挙する

統計量 <code>T</code> が変換 <code>g</code> に対して <code>T(gx) = T(x)</code> を
**すべての系列で**満たすなら、その統計量は <code>g</code> に盲目である。
バッテリー全体では共通部分を取る。**そこに入った性質は、標本をいくら増やしても、
検定をいくら改善しても差を返さない。検出力が定義上 0 になる。**

これは「検出力が低い」とは質的に違う。そして**定義を見れば分かるので、
走らせる前に確認できる**（`python3 invariance.py`、10秒）。

```
変換        厳密に不変な統計量   見えているのは
scale       16/16               なし          ← 意図的にそう設計した
reversal    14/16               leverage, gain_loss_asymmetry
sign        10/16               hill_left/right, return_skewness, leverage,
                                gain_loss_asymmetry, drift
location     6/16               （平均を引く6個以外は反応する）
shuffle      5/16               時間構造を見る11個
tail         0/16               全部が反応する
```

### 時間反転に敏感で、何が良いのか

**もっともな疑問なので、正面から答える。**「盲目だから駄目」ではない。

<b>実データは時間反転に対して強く非対称である。</b>実測すると、実データの窓を
逆順にしただけで `leverage` は四分位幅の **3.68 倍**動く。つまりこれは
「あるかどうか分からない性質」ではなく、**確実に存在してかつ大きい性質**である。

そして<b>ABM が主張しているのは、まさに時間の向きを持つ命題</b>である。

- 「チャーティストは**過去の**トレンドを外挿する」
- 「エージェントは損失を出した**後で**戦略を切り替える」
- 「価格下落**が**ボラティリティ上昇**を引き起こす**」

これらは全部「A の後に B」という向きの主張である。ところが変換に不変な統計量は、
定義から <code>T(x) = T(rev(x))</code> である。したがって——

> **正しい動きを時間反転させたモデルは、14個の統計量すべてを素通りする。**

具体的には、<b>ボラティリティが先に上がって後から下落を招くモデル</b>と、
<b>下落が先でボラティリティが後から上がるモデル</b>を、区別できない。
これは leverage effect 対 volatility feedback という**実際に決着していない論点**であり、
金融計量では長く議論されてきた（Bekaert & Wu, Campbell & Hentschel）。

**つまり、機構を主張するモデルの、機構の向きが検証されていない。**
ABM が誘導形モデルに対して持つ唯一の売りが機構なのだから、ここは効く。

<b>限界も書いておく。</b>反転に盲目であることは、そのモデルが間違っている証拠ではない。
**主張した向きが検証されていない**というだけである。時間の向きについて何も
主張していない研究なら、盲目でも構わない。

### 文献への適用

不変性の判定にシミュレーションは要らないので、**論文が挙げている組み合わせに
そのまま当てられる。**文献監査の該当論文（本文が取れ、市場シミュレーションで、
スタイライズドファクツに言及しているもの）で計算した。

```
定義                      該当  location  scale  sign  reversal  shuffle  tail
言及 1回以上              40本      0%    100%   25%     85%       5%     0%
言及 3回以上              26本      0%    100%    8%     81%      12%     0%
数値の近くにある          24本      0%    100%   17%     79%      25%     0%
図表のキャプションに出る  15本      0%    100%    7%     87%      33%     0%
報告（数値∪キャプション） 25本      0%    100%   12%     80%      24%     0%
```

**5つの定義すべてで、時間の向きに盲目な論文は8割前後で動かない。**

当初は「言及」しか数えていなかったので、「序論で列挙しただけの論文を
報告したものと同一視している」という反論が成り立った。そこで
`audit/reported.py` を足し、**54本すべてを arXiv から取り直して**
より厳しい2つの signal を取った。

- **図表のキャプションに名前が出るか**（LaTeX の `\caption{}` / arXiv HTML の `ltx_caption`）
- **言及の前後 120 字に数値があるか**（「leverage effect is well documented」ではなく
  「the leverage correlation is −0.09」の側を拾う）

厳しくすると「そもそも1つも報告していない」論文が落ちるので該当本数は減るが、
**盲目率そのものは安定している。**`leverage` を報告している論文は 5/54（9%）で、
言及ベースの 6/54（11%）とほとんど変わらない。

**操作化は両方向に外す。**統計量名を含まないキャプション
（"Table 3: Simulation results"）は見落とし、関連研究での他人の測定値の引用
（"Cont (2001) reports a tail index of 3.0"）は拾いすぎる。
**真の報告集合は「言及」と「報告」の間にある**が、上の表のとおり
その区間のどこを取っても結論は変わらない。

（n=54 と小さいこと、正規表現による自動抽出であることも `audit/README.md` に開示してある。）

## ② 推論監査 — 判定手続きそのものの誤り率を測る

この分野の標準的なやり方はこうである。実データから重なる窓を切り出し、複数指数を
プールし、生成器の実行と比べて、置換検定で p 値を出す。**v0.1 の本ベンチもそうだった。**

`selftest.py` は、**答えが分かっている人工データ**で誤り率を直接測る。
実データと同じ形の依存を持つ標本を、**同じ分布から作った独立な標本**と比べる。
差は無いので、5% 水準の棄却率は 5% であるべきである。

```
同時期の窓どうしの似かた   1本ずつ貼り替え   ブロックごと   ブロックを引き直す
rho = 0.0                    3.7%           4.7%          9.3%
rho = 0.3                   36.0%          11.3%         10.0%
rho = 0.6                   55.7%          12.7%         11.3%
```

**名目 5% に対して実際 56%。**「p 値がやや甘い」ではなく、検定として壊れている水準である。
原因は、窓が 250 日ずつずらしただけで隣と 75% を共有し、同時期の6指数が
同じ暴落を共有しているのに、**窓を1本ずつ交換可能として扱っていた**こと。

### 直すと、独立情報が無いことが露呈する

**「補正法が無い」わけではない。**暦ブロック単位の randomization inference、
block bootstrap、wild cluster bootstrap、HAC、モデルベースの推論など、依存を保つ方法は
存在する。本ベンチが測ったのはそのうち2つだけである。

消せないのは手法ではなく**情報量**である。25年を4年窓で見れば独立な暦は6個しかない。
正しく補正すると、それが**p 値の刻み**として表に出る。

```
参照対照            設計        割り当て   p の刻み   実際の最小 p
米欧 vs アジア      対応あり     64通り     0.016      0.031
S&P500 vs FTSE      対応あり     64通り     0.016      0.156
```

ブロックが6個なら割り当ては 2⁶ = 64 通りしかない。**判定線 p < 0.01 には構造上到達できない。**
検定の欠陥ではなく、独立な暦が6つしかないという事実そのものである。

したがって閾値を較正して使う。**名目 p < 0.01 で真の大きさが 3〜5% に収まる。**
代償も測ってある——この判定線での検出力は、標準偏差が 1.5 倍ずれた相手で **8.7%** しかない。
**差が出ないことは、統計量が鈍い証拠にならない。**

## ③ 補助：機構の ablation と識別行列

上の2つを支える材料として、以下も測ってある。**主役ではない。**

- **`knockout.py`** — 1つのパラメータ以外を完全に揃えて比べる。
  `leverage` は非対称性の除去に 0.68、`gain_loss_asymmetry` は 0.30 で反応し、
  どちらも裾の除去には 0.06 しか反応しない（特異性がある）
- **`separation.py`** — 実データ vs 8生成器の識別行列。全8を落とせるのは
  **`gain_loss_asymmetry` だけ**（最悪 p = 0.0010）。`leverage` は
  `block_bootstrap` に届かず 7/8
- **`sensitivity.py`** — 実装の自由度に値が引きずられていないかの検査（再発防止）

## v0.3 で直したこと —— 行列が「機構 × 検出器」になっていなかった

### A. パラメータを S&P500 だけに当てていた（交絡）

v0.2 は GARCH 族と student-t を **S&P500 だけ**に当て、それを6指数すべての
基準線に使っていた。すると KS(実データ, GJR-t) = 0.53 が出ても、その 0.53 には

- GJR が実データの非対称性を持たないこと（**測りたいもの**）
- S&P500 と日経・ハンセンのボラティリティ水準・裾・持続性の違い
- 構造変化、推定パラメータのずれ

が全部入っている。**「GJR が leverage を持たないから 0.53 になった」とは
識別できない。**あれは「生成器 × 統計量」の行列であって、まだ
**「既知の欠落 × 検出器」の行列ではなかった。**

v0.3 は**指数ごとにその指数自身のパラメータを当て**、生成もその指数のパラメータで
行ってからプールする。ブートストラップも指数内で引く。実データ側の窓の指数構成
（22/22/22/21/21/16）に合わせて生成数を割り当てる。市場間の異質性が両側に等しく
入るので、差として残るのは機構の欠落に近づく。

**結論が変わった。**v0.2 は「`leverage` だけが全8生成器を落とした」だったが、
指数ごとに当て直すと `block_bootstrap` に対して 0.25（p = 0.042）に落ち、7/8 になる。
代わりに **`gain_loss_asymmetry` が全8を落とす**（最悪 p = 0.0010）。
ただしこれは v0.3 で**その統計量のバグを2つ直した後**の話である（下の D 節）。

逆に非対称モデルに対しては**強くなった**（`gjr_t` 0.53 → 0.61、`egarch_t` 0.33 → 0.50）。
v0.2 の値は、機構の差と市場の異質性が打ち消し合っていた分だけ低く出ていた。

### B. それでも「実データ vs 生成器」では機構に帰属できない

指数を揃えても、生成器と実データは同時に何もかも違う。帰属するには、
**比較の両側を1つのパラメータ以外まったく同じにする**しかない。

`knockout.py` を足した。基準は指数ごとに当てた GJR-t（クラスタリング・重い裾・
非対称性を全部持つ）で、そこから機構を**1つだけ**抜く。

```
no_asymmetry   (alpha, gamma) → (alpha + gamma/2, 0)
no_fat_tails   nu → 30（実質正規）
no_clustering  (alpha, gamma, beta) → (0, 0, 0)
```

**`no_asymmetry` は α に γ/2 を足し戻している。**単に γ=0 にすると持続性が
0.988 から 0.876 に落ち、クラスタリングまで一緒に抜けてしまう。γ/2 を α に移せば
r² の係数の期待値も持続性も無条件分散も変わらず、**符号への依存だけ**が消える。

```
統計量                     no_asymmetry   no_fat_tails   no_clustering
------------------------------------------------------------------
leverage                       0.68           0.06           0.79
gain_loss_asymmetry            0.30           0.06           0.26
hill_right                     0.27           0.21           0.57
excess_kurtosis                0.25           0.34           0.62
aggregational_gaussianity      0.17           0.32           0.24
acf_abs_1                      0.18           0.07           0.94
ljung_box_sq                   0.11           0.17           0.95
vol_of_vol                     0.15           0.16           0.99
drift                          0.06           0.03           0.06
```

**これで初めて機構に帰属できる。**`leverage` は、**この controlled ablation では**
非対称性の除去に選択的に反応し（0.68、次点 0.27）、**裾の除去には顕著な反応を
示さない**（0.06、p = 0.53）。

**「p = 0.53 だから影響ゼロ」とは言わない。**非棄却は影響が無いことの証明ではない。
言えるのは「この標本規模で検出できるほどの反応は無く、KS も 0.06 と小さい」までで、
識別の特異性を示す材料としてはそれで十分である。

ただし `no_clustering` にも 0.78 で反応するので、**純粋な非対称性の検出器ではない。**

**この設計には依存の問題が無い。**両側とも独立な生成器の実行なので、窓の重なりも
指数間相関も無く、標準の置換検定がそのまま厳密に使える。6ブロック制約
（p の刻み 0.016、検出力 8.7%）はここには掛からない。

**限界は外的妥当性のほうに移る。**言えるのは「GJR-t 族の中で、その機構を抜いた
ことに気づくか」までで、現実の非対称性が GJR の形をしている保証は無い。
実データとの比較を置き換えるものではなく、そちらの解釈を可能にするものである。

### C. 副産物 —— 生成器行列の数字が何を測っていたか

`drift` は実データ vs 生成器では2生成器を落とすのに、**3つの機構のどれを
抜いても 0.03〜0.06 で無反応**である。つまりそこで出ていた分離は、
機構の欠落ではなく別の何か（市場の異質性、モデル族全体の形）を拾っている。
**生成器行列の数字を「その機構を検出した」と読んではいけない。**

（`gain_loss_asymmetry` も当初は 0.06 で無反応に見えていた。
**あれは統計量自身のバグだった。**次節。）

### D. `gain_loss_asymmetry` に2つのバグがあった —— そして再発防止

**この統計量の値は、現象ではなく実装が作っていた。**バグは2つ。

**1. 選抜バイアス。**「両方向とも `horizon` 以内に到達した起点だけ使う」としていた。
だが**片側だけ届かない起点こそが、測りたい非対称そのもの**である。それを
「観測できなかった」という理由で捨てていた。

```
打ち切られた起点   55%      40%      24%      14%
実データの値      +0.398   +0.307   +0.105   +0.043
```

`horizon` を延ばして打ち切りを減らすほど効果が消える。**+0.42 という報告値は、
現象ではなく捨て方が作っていた。**

**2. ドリフト汚染。**長い地平ではドリフトが非対称性を上書きし、符号が反転していた
（t=200日で −0.158）。短期（〜20日）には本物の非対称があり、平均を引くと残る。

```
t(日)          2      4      7     10     15     20     30     50    200
実データ      +0.005 +0.013 +0.025 +0.032 +0.028 +0.018 -0.006 -0.057 -0.158
平均除去後    +0.005 +0.015 +0.031 +0.044 +0.052 +0.054 +0.054 +0.033 -0.019
```

直した版（全起点の部分分布・平均除去・短期側の平均）はパラメータに鈍い
（`horizon` 150〜1000 で 0.0424〜0.0440）。

**そして結論が3つ変わった。**

| | 壊れた版 | 直した版 |
|---|---|---|
| 実データ vs 生成器 | 6/8 | **8/8（唯一の全勝）** |
| knockout の `no_asymmetry` | 0.06（無反応） | **0.30（leverage に次ぐ）** |
| GJR / EGARCH は出すか | 出さない（符号が逆） | **出す（実データの 74〜80%）** |

「標準的な生成器は gain/loss asymmetry を出さない」と一度書いたが、**あれは
こちらの測定バグだった。**GJR も EGARCH も出している。

### 再発防止 —— 「測っていたのに読まなかった」を潰す

**バグ2は、既に検出されていた。**`invariance.py` は location への反応を 0.63
（全16統計量中3位）と出していた。**出力を読んでいなかっただけである。**
バグ1は、誰も `horizon` を振っていなかった。

つまり今回の失敗は知識不足ではなく、**報告書は読み飛ばせる**という性質にある。
そこで**意図を機械可読で宣言し、実測と食い違ったら落ちるようにした。**

`facts.SPEC` に統計量ごとの設計契約を書く。

```python
"gain_loss_asymmetry": dict(
    must_invariant=("location", "scale"),          # 破れていたらバグ
    params={"rho": (3.0, 4.0, 6.0),                # 値がこれに鈍いことが要件
            "horizon": (150, 250, 500),
            "tmax": (20, 30, 50)}),
```

- **`invariance.py`** が `must_invariant` を検査する。違反があれば終了コード 1
- **`sensitivity.py`**（新規）が `params` を振り、値の振れ幅を窓どうしの
  ばらつき（四分位幅）で割って報告する。**1.0 を超えたら失敗**

後者は既に5件の警告を出している。

```
統計量                 自由度    振り幅/四分位幅
vol_of_vol            win           0.95   警告
leverage              lags          0.94   警告
hill_left             frac          0.92   警告
acf_abs_decay         lags          0.76   警告
variance_ratio_20     q             0.56   警告
gain_loss_asymmetry   horizon       0.21          ← 直した後
```

**`leverage` の lags が 0.94** ——主役の統計量が、ラグ数の選び方に四分位幅と
同じだけ引きずられている。ただしこれは**水準の移動**であり、2標本比較では
両側が同じだけ動くので、分離度への影響はこれとは別に測る必要がある。
`hill_left` の `frac` は v0.1 から限界として挙げていたもので、
**特別扱いだった検査が全統計量に自動で掛かるようになった**形である。

**報告書は読み飛ばせるが、失敗するテストは読み飛ばせない。**

## v0.2 で直したこと

**v0.1 の p 値は無効だった。**そのほか、レビューを受けて7点直した。

### 1. 置換検定の交換可能性が破れていた（最優先で修正）

v0.1 は実データ 124 本と生成 200 本を1つのプールに入れ、**ラベルを完全に
ランダムに入れ替えて** p 値を出していた。これは 324 個が交換可能という仮定だが、
実データの窓は交換可能ではない：

- 窓長 1000・ストライド 250 なので、隣り合う窓は 75% を共有する
- 2008年や2020年の窓は6指数すべてに同時に現れる
- EURO STOXX 50 は DAX 構成銘柄を含むので一部は二重計上

`robustness.py` で実効標本数を出してはいたが、**それは区間の話であって、
p 値そのものは直していなかった。**

どれだけ壊れていたかを `selftest.py` で直接測った。実データと同じ形の依存を
持つ標本を、**同じ周辺分布**から作った独立標本と比べる。帰無仮説は真なので
棄却率は 5% であるべきである：

```
ブロック内相関      完全置換(v0.1)   ブロック置換   ブロック復元抽出
rho = 0.0               3.7%          4.7%          9.3%
rho = 0.3              36.0%         11.3%         10.0%
rho = 0.6              55.7%         12.7%         11.3%
```

**名目 5% に対して実際は 56%。**交換の単位を窓1本から暦ブロックに上げると
（`resampling.block_boot_test`）大きく改善する。

### 2. これは「補正法が無い」という話ではない

構造はこうである。

```
窓が 250 ずつ重なる                   →  系列方向の依存
同時期の6指数が共通ショックを受ける    →  横断方向の依存
                    ↓
        見かけの標本数 124 ≫ 独立な情報単位
                    ↓
   観測単位での置換が依存構造を壊す（交換可能性が成立しない）
                    ↓
            size が 5% → 56% に膨張
                    ↓
  依存を保つ推論は擬似反復を避けられる。**手法は存在する。**
                    ↓
   ただし独立な暦ブロックは6個しか残らない → 解像度も検出力も本質的に低い
```

**「どの手法でも直らない」は言い過ぎである。**暦ブロック単位の randomization
inference、block bootstrap、wild cluster bootstrap、HAC、モデルベースの推論など、
依存構造を保つ方法は存在する。本ベンチが測ったのはそのうち2つだけである。

消せないのは手法の側ではなく**情報量の側**である。25年を4年窓で見れば独立な暦は
6個しかなく、どの手法もそれ以上の情報を作れない。クラスタ数が 20 を切ると
過剰棄却するのは計量経済で広く知られている（Cameron, Gelbach & Miller 2008）。
平滑化で tie の副作用を消しても改善しないことは確認した。

つまり正確な結論は——
**補正法が無いのではなく、正しく補正すると、元々データに無かった独立情報の
欠如が露呈する。**

そこで名目の閾値を下げて較正した：

```
ブロック内相関     alpha=0.05   alpha=0.02   alpha=0.01   alpha=0.005
rho = 0.2            12.0%         5.2%         3.2%         2.2%
rho = 0.4            12.0%         6.6%         4.2%         1.8%
rho = 0.6            10.6%         5.2%         4.8%         3.0%
```

**名目 p < 0.01 で真の大きさが 3〜5% に収まる。**以下の表の `*` はこの線である。

**この較正には代償がある。**同じ `selftest.py` で測ると、判定線 p < 0.01 での
検出力は、平均が 0.5σ ずれた相手で 32%、標準偏差が 1.5 倍ずれた相手で **8.7%** しかない。
**分離が出ないことは、統計量が鈍い証拠にならない。**逆に、下の表で p が小さい行は
それだけ大きな差だということである。

### 2b. 露呈のしかた —— p 値の解像度

実データ同士の対照では、両側が**同じ暦ブロックを共有している。**2008年の米欧と
2008年のアジアは同じショックを受けているので、独立な単位ではない。
v0.2 の途中まではこれを対応なしのブロック置換で検定していた。設計として誤りである
（帰無分布が広くなる方向なので保守側ではあった）。

正しくは**ブロックごとに群ラベルを入れ替える**（`resampling.paired_block_test`）。
そして、そうすると割り当ては **2^6 = 64 通りしかない。**64通りを全列挙して
p 値を出している。

```
対照            設計              割り当て   p の刻み   実際の最小 p
region          paired_block         64通り    0.016      0.031
era             unpaired_block       35通り    0.029      0.030
gspc_vs_ftse    paired_block         64通り    0.016      0.156
gspc_split      paired_block         64通り    0.016      0.125
```

**どの対照も、上で決めた判定線 p < 0.01 に構造上到達できない。**
検定の欠陥ではない。独立な暦が6つしか無いという事実が、そのまま p 値の
刻みとして表に出ている。5% 水準で精密な推論をする設計として、
**このデータはもともと解像度が足りない。**

### 3. 「天井」という呼び方をやめた

v0.1 は米欧 vs アジアの KS を「天井」と呼んでいた。これは行き過ぎだった。
取引制度・通貨・産業構成・期間が違う2群の差より生成器との差が小さいからといって、
その生成器が対象市場を再現している証拠にはならない。

**参照対照**（現実どうしのばらつきの一例）と呼び直し、参照を4つに増やした。
同じ市場の別時代、最も似た2市場、同一市場・同一時代の分割まで並べる。

### 4. 周辺分布を16個並べるだけでは足りない

個別の KS を16回やると、どれも個別には合っているのに同時分布が現実と全く違う
生成器を通してしまう。統計量ベクトル全体の **energy 検定**を足した（総合層）。
個別の KS は「何が壊れているか」の診断として残す（総合スコアだけでは説明できない）。

### 5. 多重性

16統計量 × 8生成器 = 128 セル。Benjamini-Hochberg の q 値を出す。

ただし「**この統計量は全生成器を落とせる**」という主張には補正は要らない。
全部が有意であることを要求する側は交差-合併検定であり、もともと水準を超えない。
補正が要るのは「どこかに有意差がある」を探す側だけである。

### 6. 梯子に非対称なボラティリティ・モデルが1つも無かった

v0.1 の結論は「効いたのは `leverage` だけだった」。だが `garch_norm` / `garch_t` は
どちらも**対称な**モデルである。対称なモデルが非対称性の指標で落ちるのは
ほとんど定義から従う。**非対称なモデルが梯子に無い状態では、何も試されていない。**

GJR-GARCH と EGARCH を足した。**この2つは `leverage` を選んだ後に足したので、
v0.1 の統計量選択に対して純粋に held-out である。**選択用と評価用の分離が、
ここで初めて1つだけ実現している。

同時に `garch_t` の推定を直した。v0.1 は**正規尤度で当てた**パラメータに後から
t 分布のイノベーションを載せていた。ここでは (ω, α, β, ν) を同時に最尤推定する。

### 7. `gain_loss_asymmetry` は歪度だった

v0.1 の `gain_loss_asymmetry` は標準化3次モーメント、つまりただの歪度である。
金融でいう gain/loss asymmetry は通常、利得側と損失側の**到達時間**の非対称
（Jensen, Johansen & Simonsen 2003 の inverse statistics）を指す。名前が実装を
誤って表していた。

- 旧実装 → `return_skewness` に改名（値は変わらない）
- `gain_loss_asymmetry` → 到達時間版として新規に実装

新しいほうは実データで中央値 +0.42（上げは下げより 52% 長くかかる）、
ガウス生成器で −0.12 とほぼ 0 になる。文献の記述どおりに振る舞う。

### 8. 実装の verification と validation を分けた

`models/status.py` に、モデルごとの状態を機械可読で持たせた。

```
                            franke_westerhoff       chiarella_iori
specification_conformance            verified              partial
invariant_tests                          pass                 pass
paper_replication                        pass                 fail
empirical_validation                     fail              not_run
```

上3行が verification（論文どおりに動くか）、最終行だけが validation（現実と合うか）。
**Franke-Westerhoff は論文 Table 2 を8つとも再現するのに、実データとの照合では
落ちる。**この2つは別の問いである。不変量は宣言ではなく実際に走らせて確かめる
（Chiarella-Iori の株式・現金の保存は相対誤差 0.0）。

## 生成器の梯子

比較対象には、正解が分かっている生成器を並べる。目的は落とすことではなく、
**落とせないことを見つけること**にある。

| 生成器 | 何を持っているか |
|---|---|
| `gaussian` | 何も持っていない。ここで分けられない統計量は使い物にならない |
| `student_t` | 重い裾。時間構造なし |
| `iid_bootstrap` | 実データの値そのもの。時間構造だけが無い |
| `block_bootstrap` | 短期の時間構造のみ（ブロック長20） |
| `garch_norm` | **対称な**クラスタリング |
| `garch_t` | 対称なクラスタリング＋重い裾（同時最尤推定） |
| `gjr_t` | **非対称な**クラスタリング＋重い裾 **（held-out）** |
| `egarch_t` | 非対称（対数分散・指数型） **（held-out）** |

推定値（S&P500、`baselines.json`）:
GARCH-t (ω,α,β,ν) = (0.011, 0.118, 0.875, 6.47)、
GJR-t (ω,α,γ,β,ν) = (0.015, 0.000, 0.223, 0.876, 7.14)、
EGARCH-t (ω,α,γ,β,ν) = (−0.010, 0.146, −0.169, 0.974, 6.97)。
GJR の γ = 0.223 に対し α = 0、EGARCH の γ = −0.169。**どちらも実データどおりの
強い非対称性を持っている。**

`iid_bootstrap` は時間構造だけを壊す。ただし **周辺分布が一致するのはプール全体に
対してであって、個々の窓（単一指数・単一時期）に対してではない。**

## 読み取れること

**1. ボラティリティ・クラスタリングの再現は、機構については何も言わない。**

`acf_abs_1` は ABM 論文が最も頻繁に載せる統計量だが、`garch_norm` に対する KS は
**0.12（p = 0.36）**で分けられない。`block_bootstrap` に対しても 0.15 で分けられない。
さらに `knockout.py` では、**非対称性を抜いても 0.18、裾を抜いても 0.06** しか動かない。
反応するのはクラスタリングの除去（0.94）だけである。

ここは v0.1 より正確に書き直す。v0.1 は「ほとんど何も証明していない」と書いていたが、
言い過ぎだった。正確には：

> ボラティリティ・クラスタリングの再現は、現象論的な妥当性の一部を示す。
> だが、**それがエージェント相互作用によって生じたことの証拠にはならない。**

クラスタリングを出せること自体は確認できている。示されていないのは、その原因が
モデルの機構であることのほうである。GARCH(1,1) と区別がつかない以上、
その主張は識別されていない。

**2. 合わせ込んだ量では判定できない。**

`ljung_box_sq` は `gaussian` / `student_t` / `iid_bootstrap` に対して 0.98〜0.99 と
ほぼ完璧に働くのに、`garch_norm` に対しては **0.06** に落ちる。GARCH はまさに
この構造に合わせて作られたモデルだからである。

**これは分子動力学の力場検証と同じ話である。**密度に合わせ込んだ力場を密度で
評価しても何も分からない。判定は**合わせ込んでいない量**でやらなければならない。

**3. `leverage` は非対称性の除去を検出する。ただし全能ではない。**

v0.2 は「判定線で全8生成器を落とせたのは `leverage` だけ」と書いていた。
**指数ごとにパラメータを当て直すとこれは成り立たない。**`block_bootstrap` に対して
0.25（p = 0.042）で判定線を越えず、7/8 になる。`multiscaling` と
`variance_ratio_20` も 7/8 で並ぶ。**全8を落とせる統計量は無い。**

一方、非対称モデルに対しては v0.2 より**強くなった**。

```
garch_norm  0.97   →  garch_t  0.92   →  gjr_t  0.61   →  egarch_t  0.50
```

そして `knockout.py` により、**この差が非対称性に由来することが初めて識別された。**
機構を1つだけ抜く実験で、`leverage` は非対称性の除去に **0.68** で反応し（次点 0.27）、
**裾の除去には 0.06（p = 0.53）で無反応**である。

**ただし純粋な非対称性の検出器ではない。**クラスタリングの除去にも 0.78 で反応する。
`leverage` は corr(r_t, |r_{t+k}|) なので、|r| に構造が無ければそもそも相関が消える。
正確には**「非対称性とクラスタリングの両方に反応し、裾には反応しない」**である。

`block_bootstrap` に弱いのは当然で、実データのリターンを20日ブロックごと再利用
するため、**ブロック内の非対称性がそのまま残る。実データを切り貼りした系列は、
実データと同じレバレッジ効果を持つ。**

**そして `leverage` は、ABM 論文でほとんど報告されない。**

**4. 自分のバグの記録（これは知見ではない）。**

v0.1 は `excess_kurtosis` が `garch_t` を KS 0.72 で落とすと報告していた。
`garch_t` の推定を同時最尤に直すと **0.18（p = 0.22）で判定線を越えない。**
v0.1 の `garch_t` は、正規尤度で当てた分散パラメータに ν = 2.65 の裾を後付けした
別物のモデルで、裾が合わないのは当たり前だった。

**これは分野に対する発見ではなく、こちらの実装ミスである。**他の研究が同じことを
していると示す証拠は無い。一般論として「基準線が弱いと統計量が強く見える」は
言えるが、**それを裏づける事例はこの自分のバグ1件しかない。**
教訓として残すが、主張の材料には使わない。

**5. 単独で全てを捉える統計量は存在しない。**

生成器ごとに、判定線を越えた統計量はきれいに食い違う。

```
block_bootstrap  acf_abs_20 0.75, acf_abs_decay 0.72, hill_left 0.23
garch_norm       leverage 0.97, excess_kurtosis 0.68, aggregational_gaussianity 0.66
gjr_t            leverage 0.61, return_skewness 0.54, gain_loss_asymmetry 0.28
egarch_t         return_skewness 0.52, leverage 0.50, ljung_box_sq 0.34
```

**互いに補い合っている。**`acf_abs_20` は `block_bootstrap` を 0.75 で捉えるが
`garch_norm` には 0.18 で無力。`leverage` は `garch_norm` を 0.97 で捉えるが
`block_bootstrap` には 0.25 で判定線を越えない。**片方だけでは必ずどちらかを見逃す。**

held-out の2つに最も効くのは `leverage` と `return_skewness` である。
GJR も EGARCH も**非対称なボラティリティは持つが、イノベーションは対称**なので、
無条件の歪度が実データと合わない。だから歪度で落ちる。
そしてその `return_skewness` は `block_bootstrap` には 0.11 で無力である。

**バッテリーが要るという主張の根拠がここにある。**

**6. 「リターンは予測できない」は検証に使えない。**

`acf_return_1` は全生成器に対して 0.13〜0.35。誰でも再現できるので情報が無い。

**7. この表に出ない失敗の仕方がある。**

`variance_ratio_20` と `drift` はここに並べた8生成器に対して弱い。表だけ見れば
無用な統計量に見える。

だがこの2つは**後から足した**もので、足した理由は生成器ではなく **ABM** にある。
既存の ABM 実装を S&P500 に較正して通したところ、実データの3〜5倍も強く平均回帰し
（VR(20) が実データ 0.75 に対して 0.13〜0.31）、ドリフトは4〜10倍あった。
**元の13個はどれもこれを直接には見ていなかった。**

```
                drift(mean/σ)   実データ比
実データ窓124本      +0.0168        —
Chiarella-Iori     +0.0678      4.0倍
Franke-Westerhoff  +0.1587      9.5倍
Zero Intelligence  +0.1443      8.6倍
```

較正側の欠陥でもあった。較正の目標3つのうち尖度と `acf_return_1` はドリフトに
盲目なので、**最適化はドリフトを好きなだけ盛れた。**ドリフトを実データの95%範囲に
制約して較正し直すと、Chiarella-Iori の損失は **0.050 → 2.830** に悪化した。
**モデルは非現実的なドリフトを使って尖度とクラスタリングを作っていた。**

**8. 平均を、誰も見ていなかった。**

上の drift は、較正した ABM の累積リターンを100本重ねて描いたときに
**人間が図を見て気づいた。**当時の14個はどれも検出できなかった。

**これを「有限のバッテリーには必ず穴がある」という一般論にするのは、ごまかしである。**
見落としたのは**一次モーメント**で、珍しい汎関数ではない。

### 言い訳の第2版も、測ったら間違いだった

一度ここに「当時の14個は構造上すべて位置に対して不変だったので、原理的に
見えなかった」と書いた。**`invariance.py` を書いて確かめたら、この主張は誤りである。**

位置の変換 x → x + c に**厳密に**不変なのは 16 個中 **6 個だけ**である
（平均を引いてから計算するもの）。残りは反応する。しかも小さくない：

```
統計量           x → x + 0.15σ に対する反応（窓間の四分位幅に対する比）
drift                4.56      ← v0.2 で足した
multiscaling         0.97      ← 当時からあった
gain_loss_asymmetry  0.63
hill_right           0.22
hill_left            0.20
（厳密に 0 なのは excess_kurtosis, return_skewness, acf_return_1,
  aggregational_gaussianity, vol_of_vol, variance_ratio_20 の6個）
```

**バッテリー全体が厳密に不変なのは `scale` だけ**である ── 意図的に入れた不変性
だけである。つまり **span{1} は共通不変集合に入っていない。**ドリフトは
原理的には見えた。`multiscaling` は四分位幅と同程度動いていた。

**したがって、見落としの原因は構造ではない。単に見ていなかった。**
最初にそう指摘されたときの答えが正しく、「不変性」への言い換えは、
より洗練された同じ言い訳だった。**2回同じことをやったので、ここに残しておく。**

### 監査そのものは残る。そして別のものを見つけた

不変性の監査という**手続き**は正しい。走らせる前に、定義から
「絶対に見えないもの」が分かる。実際に走らせたら、ドリフトより深刻なものが出た。

```
変換            厳密に不変な統計量（＝原理的に検出できない）
scale           16/16   ← 意図的
reversal        13/16   時間の向き。見えるのは leverage, gain_loss_asymmetry, vol_of_vol だけ
sign            10/16   上げ下げの非対称
location         6/16
shuffle          5/16   時間の並び全体（純粋な周辺分布の統計量）
tail             0/16
```

**この列に載っている統計量だけを報告する研究は、その性質を原理的に検出できない。**
標本を増やしても、検定を改善しても、Monte Carlo を回しても変わらない。
これは検出力が低いのとは質的に違う ── **検出力が定義上 0 になる。**

### そして、これは文献にそのまま当てられる

不変性の判定にシミュレーションは要らないので、**論文が挙げている組み合わせに
直接適用できる。**`audit/relabeled.json` の 54 本（うち統計量に写せた 40 本）でやると：

```
                    しきい値 ge1        しきい値 ge3
時間の向きに盲目      34/40 (85%)        21/26 (81%)
上げ下げの非対称に盲目  10/40 (25%)         2/26 ( 8%)
```

**8割の論文が、時間の向きに対して原理的に盲目な組み合わせを使っている。**
リターンの系列を逆再生しても、それらの統計量は同じ値を返す。
「レバレッジ効果はほとんど報告されない」という観察は、
**「その論文たちには時間の非対称性が検出できない」という証明可能な主張**に格上げできる。

（監査は「言及」を数えているので「報告」より広い。したがってこの判定は
**保守側**である ── 実際に報告している統計量はより少ないはずで、
盲目な変換はもっと多い可能性が高い。）

### AUC 版について

v0.1 の初期は power = 2|AUC − 0.5| を使っていた。AUC は確率的順序、つまり
位置ずれしか見ないので、中心が同じで形が違う分布にほぼゼロを返す：

```
中央値同一・分散5倍差   power 0.138   KS p = 2.7e-13
二峰性 vs 単峰         power 0.003   KS p = 2.2e-17
```

さらに雑音床が測られていなかった（同一分布同士でも 124 対 200 なら平均 0.052）。
`run_power.py` と `power.json` に比較用として残してある。

## 統計量の選び方について（開示）

**`variance_ratio_20` と `drift` は、ABM の失敗を見てから足した。**そして同じ ABM に
対する分離度を報告している。これは選択的推論の問題であり、
**経緯を開示しても補正にはならない。**

v0.2 で一歩だけ進んだ。`gjr_t` と `egarch_t` は統計量を選び終えた後に足したので、
**この2列に対する数字は選択の影響を受けていない。**`leverage` が全生成器を
落としたという結論は、この held-out 2列を含んだうえでのものである。

ただしまだ足りない。次の版では最初から3つに分ける：

- **Discovery models** — 統計量を見つけるためだけに使う
- **Development models** — 実装の調整に使う
- **Hidden challenge models** — 最終評価だけに使い、開発中は見ない

なお `gain_loss_asymmetry`（到達時間版）は v0.2 で新規に足したが、これは
**名前と実装を一致させるため**であって、識別力を見てから足したものではない
（実装してから初めて数字を見た）。

**公開後には逆向きの同じ問題が起きる。**このベンチに合わせ込む（Goodhart 化）
動機が生じ、上の「読み取れること2」がベンチ自身に跳ね返る。

## 正直に書いておく限界

1. **LLM シミュレーションをまだ通していない。**今あるのは既知の生成器だけである。
   意味があるのは、公開されている LLM エージェント市場シミュレーションの
   出力を通した時点から。**これが本番。**
2. **独立な暦ブロックが6個しかない。**これが全ての精度を縛っている。
   検定は名目水準を達成できず（較正で対処）、検出力も低い（標準偏差1.5倍の
   ずれを 8.7% しか捉えられない）。実データ同士の対照では p の刻みが 0.016 になり、
   判定線に届かない。**これは推論手法の問題ではなく実験単位の不足**なので、
   統計手法では解けない。指数を増やすか、窓を短くするしかない
3. **実効標本数の v0.1 の推定は甘かった。**v0.1 は窓の通し番号 k を「同じ時期」の
   代理に使っていたが、営業日数が指数ごとに違い、EURO STOXX 50 は開始が5年半遅い。
   暦で測り直すと実効標本数の中央値は **48 → 23**（名目124に対し 5.5 倍の希釈）。
   v0.1 が書いていた「1.59倍に広げるべき」は過小だった
4. **ブロックの継ぎ目。**ストライド 250・窓長 1000 なので窓は数珠つなぎで、
   完全に独立なブロックには分けられない。区切りの直前と直後の窓は最大 99% を
   共有する。ブロック化はこの継ぎ目を許した近似である
5. **GARCH 系は S&P500 のみで推定**し、それを全指数の基準線として使っている
6. **`student_t` の自由度 2.65 について。**v0.1 はこれを「極値に引かれたバイアス」と
   書いていたが、正確には**無条件分布への iid-t の最尤推定値**である。同時最尤推定に
   よる**条件付き**イノベーションの自由度は 6.47（`garch_t`）で、こちらが通常
   報告される値。別の量を推定しているだけで、どちらも誤りではない
7. **日次のみ。**日中データを入れると、マイクロ構造由来の統計量が追加できる
8. **統計量は16個。**Cont (2001) の主要な事実は覆っているが、網羅ではない。
   14個目と15個目はどちらも ABM を通して初めて必要と分かったもので、
   **同じことがまだ他にも起きうる**
9. **`aggregational_gaussianity` が不安定。**データを 36,073 点から 36,079 点に
   変えた（各指数の先頭に1〜2日足しただけ）ところ、この統計量だけ大きく動いた。
   **現在の窓数では推定量の分散が大きすぎる**
10. **Hill の k を 5% に固定している。**k を 2.5%→10% と振ると実データの推定値が
    3.54→2.97、`garch_t` に対する KS が 0.14→0.27 に動く。
    **`hill_*` の行は k の選択に依存している**
11. **梯子はまだ失敗の仕方を網羅していない。**v0.2 で非対称ボラティリティを足したが、
    確率的ボラティリティ、レジーム・スイッチング、長期記憶（FIGARCH / HAR）、
    時系列 GAN は入っていない。構造を持つモデル（ABM や LLM エージェント）が
    起こす壊れ方も、`variance_ratio_20` と `drift` で見たとおり別枠である
12. **同等性検定になっていない。**現状は「差が有意か」を見ている。認証基盤にするなら、
    参照対照から許容幅を決めて**非劣性・同等性検定**にすべきである。まだやっていない

13. **「報告」の操作化はまだ機械的である。**`audit/reported.py` で図表キャプションと
    数値近傍を見るところまでは上げた（5つの定義すべてで盲目率 79〜87%）が、
    統計量名を含まないキャプションは見落とし、関連研究での引用は拾いすぎる。
    **決着させるには 54本を人手で読むしかない。**規模的には可能である
14. **反転に盲目であることは、そのモデルが誤りである証拠ではない。**主張した機構の
    向きが検証されていない、というだけである。時間の向きについて何も主張していない
    研究なら問題にならない
15. **宣言した変換は6つだけ。**網羅ではない。持続性・長期記憶・レジームに対応する
    変換は、点ごとの写像として素直に書けないので入っていない

**1 が本番。2 が全体を縛っている。13 は機械化の限界で、人手で潰せる。**

## 何のためにやっているか

生成的シミュレーションが企業や金融機関の意思決定に入り始めている一方で、
**その出力が現実と同じ形をしているかを、生成した側から独立に判定する手続きが
存在しない。**各社が自ら採点した妥当性スコアを公表している状態にある。

判定を作るには、まず**判定に使える統計量とそうでない統計量を分ける**必要がある。
この表はその最初の一枚である。

そしてこのリポジトリの本体は、16個の統計量そのものではなく、
**「観測量 × 欠陥機構」の識別行列**である。統計量 T_j と既知の欠陥を持つ生成器 M_k に
対して D_jk = separation(T_j(実データ), T_j(M_k)) を埋めていく。
上の表がその行列で、`selftest.py` はその測定装置自体の校正証明書にあたる。
