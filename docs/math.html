1. 統計量とは「圧縮」である — 何かは必ず捨てられる

何に困っているか

1000営業日ぶんのリターン系列があります。これは 1000 個の数です。 そこから「尖度は 4.2 だった」と報告する。1000 個が 1 個になりました。 差し引き 999 個ぶんの情報はどこかへ消えています。

問題は、何が消えたのかを普通は誰も確かめないことです。 消えたものが、たまたま検証したかった性質だったら、その検証は最初から成立しません。

定義

系列全体の集合を X、実数を ℝ と書きます。 統計量とは、系列を1つの数に落とす写像のことです。

T : X → ℝ 系列 x を入れると、数 T(x) が1つ出てくる

本ベンチには 16 個あるので、それぞれ T1, T2, …, T16 と番号を振ります。 まとめてバッテリー（電池ではなく「一式」の意味）と呼び、 B = {T1, …, T16} と書きます。

具体例
T_lev(x) = リターン r_t と、その後の |r| との相関   → leverage
T_kurt(x) = 標準化したリターンの4乗平均 − 3          → excess_kurtosis

どちらも 1000 個の数を受け取って、1 個の数を返します。

この研究での使われ方

実データの窓 124 本それぞれに T を当てると、数が 124 個できます。 生成器の実行 200 本に当てると、数が 200 個できます。 この2つの集まりがどれだけ違うかが、本研究の測っているものです。

ここで一度立ち止まる必要があります。 そもそも T がその違いを保存していなければ、 いくら比べても差は出ません。次章がそれです。

2. 不変性 — 「原理的に見えない」の正体

何に困っているか

ある ABM（エージェントベース・モデル）が、実データの 10 倍の右肩上がりを持っていました。 累積リターンの図を描くと、ほぼ直線のランプで、目で見れば一発で分かる異常です。 ところが当時の 14 個の統計量は、どれ一つ検出しませんでした。

これが「たまたま見逃した」なのか「原理的に見えなかった」なのかは、 まったく違う話です。前者はデータを増やせば直ります。後者は永久に直りません。 そしてどちらなのかは、定義を見れば分かります。

定義

系列に何か操作を加えることを考えます。この操作を 変換 と呼び、 g と書きます。gx は「x に g を施した系列」です。

本研究で宣言している6つの変換
名前操作対応する性質
locationx → x + c位置・ドリフト
scalex → a·x尺度・ボラティリティ水準
signx → −x上げ下げの非対称
reversal系列を逆順に時間の向き
shuffleランダムに並べ替え時間の並び全体
tailx → sign(x)|x|1.3裾の重さ

網羅が目的ではありません。検証したい性質に対応する変換を、先に宣言しておくことが目的です。

さて、統計量 T が変換 g に対して 不変である、とは次のことです。

T(gx) = T(x)　　（すべての x について） 「たまたま今回のデータで一致した」ではなく、どんな系列でも必ず一致する

数値例 ① — 平均を引く統計量は、位置に不変

短い系列で実際に確かめます。x = (1, −2, 3, −1, 4)、 これに c = 10 を足します。

x       = ( 1, −2,  3, −1,  4)     平均 =  1
x + 10  = (11,  8, 13,  9, 14)     平均 = 11

x − 平均       = ( 0, −3,  2, −2,  3)
(x+10) − 平均  = ( 0, −3,  2, −2,  3)      ← 完全に同じ

足した 10 は、平均を引く段階で きれいに打ち消されます。 式で書けば (xt+c) − (x̄+c) = xt − x̄ です。 尖度も歪度も、この「平均を引いた列」だけから計算されるので、 足した 10 は最初の一手で消えてしまい、その先には一切届きません。

これは実験結果ではありません。定義から必ずそうなります。 データを 100 倍にしても、検定を改良しても、Monte Carlo を何億回回しても変わりません。

数値例 ② — 絶対値を経由すると、不変ではなくなる

同じ系列で、今度は絶対値を取ってみます。

|x|      = ( 1,  2,  3,  1,  4)
|x + 10| = (11,  8, 13,  9, 14)     ← 全然違う列になった

|x+c| ≠ |x|+c なので、絶対値を経由する統計量は位置に不変ではありません。 実測すると acf_abs_1 は −0.76 から −0.62 に動きました。反応しています。

ここが決定的な区別です。

厳密に不変なら、検出力は定義上ゼロ。データを増やしても永久に見えません。
反応するが小さいなら、検出力が低いだけ。標本を増やせば見えるようになりえます。

バッテリー全体の不変性

統計量ごとに、不変な変換の集まりを Gj と書きます。

Gj = { g : Tj(gx) = Tj(x)　すべての x で }

バッテリー全体が不変な変換は、その共通部分（全部に共通して入っているもの）です。

GB = G1 ∩ G2 ∩ … ∩ G16 ∩ は「両方に入っているものだけ集める」という記号

なぜ共通部分なのか。16 個のうち 1 個でも反応するなら、その 1 個で気づける可能性があります。 「バッテリー全体に見えない」と言うためには、16 個すべてが同時に不変でなければなりません。

g ∈ GB（g が共通部分に入っている）なら、

( T1(gx), …, T16(gx) ) = ( T1(x), …, T16(x) ) バッテリーから見て x と gx は同じ物である

この研究での使われ方 — invariance.py

16 個 × 6 変換の 96 セルを、実データ 124 窓で実際に走らせて分類しました。 相対変化が計算機精度なら「厳密に不変」、窓間のばらつきの 5% 未満なら「ほぼ不変」、それ以上なら「反応」です。

変換厳密に不変な統計量の数意味
scale16 / 16全部不変。意図的にそう設計した
reversal13 / 16時間の向きが見えるのは3個だけ
sign10 / 16上げ下げの非対称が見えない
location6 / 16平均を引く6個
shuffle5 / 16純粋に分布の形だけを見る5個
tail0 / 16全部が反応する

この監査は、私が書いた説明を1つ否定しました。

「14 個すべてが位置に不変だったからドリフトは原理的に見えなかった」と一度書きました。 測ったら違いました。位置に厳密に不変なのは 6 個だけで、 multiscaling は四分位幅と同じくらい（0.97）動きます。 バッテリー全体が厳密に不変なのは scale だけ——意図して入れた不変性だけです。

つまりドリフトは原理的には見えた。見なかっただけです。 「不変性」による説明は、より洗練された言い訳でした。

それでも監査は、もっと強いものを見つけた

不変性の判定にシミュレーションは要りません。定義だけで決まります。 ということは、他人の論文にもそのまま当てられます。

文献監査の該当論文（本文が取れて、市場シミュレーションで、スタイライズドファクツに言及しているもの）が 挙げている統計量の組み合わせについて、その共通不変集合を計算しました。

その性質を原理的に検出できない論文言及1回以上言及3回以上
時間の向き（reversal）34 / 40（85%）21 / 26（81%）
上げ下げの非対称（sign）10 / 40（25%）2 / 26（8%）

8割の論文が、系列を逆再生しても同じ値を返す組み合わせを使っています。 「レバレッジ効果はあまり報告されない」という統計的な観察が、 「それらの論文には時間の非対称性が検出できない」という証明可能な主張に変わります。

（監査は「言及」を数えているので「報告」より広い。したがってこの判定は保守側です—— 実際に報告している統計量はもっと少ないはずで、盲目な変換はもっと多い可能性が高い。）

3. 分布を比べる — 経験分布関数と KS 統計量

何に困っているか

実データ側から 124 個、生成器側から 200 個の数が出ました。 この2つの集まりがどれだけ違うかを、1つの数で言いたい。

平均を比べるだけでは足りません。平均が同じで形だけが違うことがあるからです。 実際 v0.1 では AUC という指標を使っていて、これは位置のずれしか見ないため、 中心が同じで分散が5倍違う2つの分布に、ほぼゼロを返していました。

定義

まず 経験分布関数（ECDF）。数の集まり a に対して、

Fa(t) = （a の中で t 以下だったものの割合）

要するに「この値以下が何割か」を返す関数です。必ず 0 から始まり 1 で終わります。

数値例

a = (1, 2, 5) と b = (3, 4, 6) を比べます。

  t      F_a(t)   F_b(t)   |差|
  0      0.000    0.000    0.000
  1      0.333    0.000    0.333
  2      0.667    0.000    0.667   ← 最大
  3      0.667    0.333    0.333
  4      0.667    0.667    0.000
  5      1.000    0.667    0.333
  6      1.000    1.000    0.000

最大の差は 0.667。これが KS 統計量です。

一般に 2標本 Kolmogorov–Smirnov 統計量 は

KS = maxt | Fa(t) − Fb(t) | 2本の累積分布関数の、縦の隔たりが最も大きいところ

値は 0（完全に重なる）から 1（まったく重ならない）まで。 位置がずれても、幅が違っても、形が違っても反応します。ここが AUC との違いです。

この研究での使われ方

識別行列の各セルが、この KS です。同じ2つのデータでも、どの統計量で見るかで値が変わります。

見る統計量実データ 124 窓の中央値GARCH 200 実行の中央値KS
leverage−0.099−0.0020.93
acf_abs_1+0.193+0.2020.12

同じ実データと同じ GARCH です。違うのは、それを1つの数に落とす統計量だけ。 レバレッジ効果で見れば分布はほとんど重ならず、絶対値リターンの自己相関で見ればほぼ完全に重なります。

4. その差は偶然か — 置換検定と p 値

何に困っているか

KS = 0.12 が出ました。これは「差が無い」なのか、「本当は差があるが小さい」なのか。

実はどちらとも言えません。124 個と 200 個の数なら、まったく同じ源から取っても KS は偶然それなりの値になるからです。 比べる相手が要ります。

定義

やることは単純です。

  1. 124 個と 200 個を1つにまとめて 324 個にする
  2. どれが実データでどれが生成器かのラベルだけを、ランダムに貼り替える
  3. 貼り替えた状態で KS を計算する
  4. 2〜3 を 2000 回くり返す → KS が 2000 個できる
  5. 実際の KS 以上だったものの割合を数える

この最後の割合が p 値 です。

p = （ラベルを貼り替えて作った 2000 個の KS のうち、実際の KS 以上だった割合）
p 値の読み方（と、読んではいけない読み方）

p = 0.02 の意味：「ラベルを適当に貼り替えても、2% はこのくらいの隔たりが出る」。 つまり偶然でも起こりうる程度かどうかの目安です。

p 値ではないもの：

  • 信頼区間ではありません。区間ではなく1つの割合です
  • 「仮説が正しい確率」ではありません。仮説が正しいと仮定した上で、 今回くらいの差が出る頻度です
  • p が大きい＝差が無い、ではありません。「この標本規模では検出できなかった」までです

この手続きが前提にしていること

ラベルを貼り替えてよいのは、貼り替えても分布が変わらないときだけです。 これを 交換可能性 と言います。

「どれが実データ側の値か」に意味が無いなら、
貼り替えても同じ分布になるはずだ これが成り立たないと、以下の p 値は全部無効になる

324 個の値が互いに独立なら、これは成り立ちます。次章で見るとおり、成り立っていませんでした。

5. 交換可能性が壊れると何が起きるか — 依存と実効標本数

何に困っているか

実データの窓 124 本は、こう作られています。

  • 長さ 1000 営業日（約4年）の窓を、250 日ずつずらして切り出す
  • それを 6 つの株価指数それぞれで行い、全部プールする

すると、

  • 隣の窓とは 1000 日のうち 750 日が同じデータです（75% 共有）
  • 2008年の窓は 6 指数すべてに同時に現れます。同じ暴落を 6 回数えている

つまり 124 本は 124 個ぶんの独立な情報を持っていません。 それなのに 1 本ずつ貼り替えると、この重なりが消えてしまいます。

どれだけ壊れるか — 測った

selftest.py は、答えが分かっている人工データで誤り率を直接測ります。 実データと同じ形の依存を持つ標本を、同じ分布から作った独立な標本と比べる。 差は無いので、5% 水準の棄却率は 5% であるべきです。

同時期の窓どうしの似かた1本ずつ貼り替えブロックごと貼り替えブロックを引き直す
ρ = 0.0（ばらばら）3.7%4.7%9.3%
ρ = 0.336.0%11.3%10.0%
ρ = 0.6（よく似ている）55.7%12.7%11.3%

名目 5% に対して実際は 56%。差が無いのに、10 回に 5〜6 回「差がある」と答えていました。 これは「p 値がちょっと甘い」ではなく、検定としてほぼ壊れている水準です。

実効標本数 — 見かけと中身の差

依存があると、標本数は見かけより少なくなります。これを表すのが 級内相関 ρ と デザイン効果 です。

deff = 1 + (m − 1)·ρ　　　　n実効 = n / deff m はブロックあたりの本数、ρ はブロック内での似かた（0〜1）
数値例
ブロックあたり m = 20 本のとき

  ρ = 0     deff = 1.00    124 本 → 124 本   （独立なら減らない）
  ρ = 0.25  deff = 5.75    124 本 →  22 本
  ρ = 0.6   deff = 12.40   124 本 →  10 本

実測した中央値は 23 本でした。名目 124 本に対して 5.5 倍の希釈です。

交換の単位を上げる

直し方は、貼り替える単位を大きくすることです。窓 1 本ではなく、 同じ時期の窓をまとめた「暦ブロック」ごと動かす。 そうすればブロック内の重なりは壊れません。

25 年を約4年の窓で見ると、暦ブロックは 6 個できます。

それでも名目には届かない — ただし「手法が無い」わけではない

ブロック法でも 10〜13% あります。ここは正確に言う必要があります。

依存を扱う手法は存在します。暦ブロック単位の randomization inference、 block bootstrap、wild cluster bootstrap、HAC、モデルベースの推論など。 本ベンチが測ったのはそのうち2つだけです。

消せないのは手法の側ではなく情報量の側です。25 年を4年窓で見れば独立な暦は 6 個しかなく、 どの手法もそれ以上の情報を作れません。

正確には——補正法が無いのではなく、正しく補正すると、 元々データに無かった独立情報の欠如が露呈する。

クラスタ数が 20 を切ると過剰棄却するのは、計量経済で広く知られています （Cameron, Gelbach & Miller 2008）。6 個はその領域の深いところです。

直せないなら、閾値のほうを動かす

誤り率が測れているなら、読み替え表を作ればよい。

同時期の窓どうしの似かたα=0.05α=0.02α=0.01α=0.005
ρ = 0.212.0%5.2%3.2%2.2%
ρ = 0.412.0%6.6%4.2%1.8%
ρ = 0.610.6%5.2%4.8%3.0%

「p < 0.01 と出たとき、本当は 3〜5% の確率で間違っている」。 だから 0.01 を 5% 水準の判定線として使います。

ただし代償があり、それも測れます。この判定線での検出力は、 平均が 0.5σ ずれた相手で 32%、標準偏差が 1.5 倍ずれた相手では 8.7% しかありません。 差が出ないことは、統計量が鈍い証拠になりません。

独立情報の不足は、p 値の刻みにも出る

実データ同士を比べるとき（米欧 vs アジアなど）、両側が同じ暦ブロックを共有します。 2008年の米欧と 2008年のアジアは 1 つのショックであって、独立な 2 単位ではありません。

正しい設計は、ブロックごとに群ラベルを入れ替えることです。そして——

ブロックが6個 → 割り当ては 26 = 64 通りしかない 各ブロックについて「入れ替える／入れ替えない」の2択が6回

64 通りしかないなら、p 値が取りうる値は 1/64 ≒ 0.016 刻みです。

参照対照設計割り当てp の刻み実際の最小 p
米欧 vs アジア対応あり640.0160.031
2014年 前 vs 後対応なし350.0290.030
S&P500 vs FTSE対応あり640.0160.156
S&P500 を二分対応あり640.0160.125

どの対照も、判定線 p < 0.01 に構造上到達できません。最小可能値が 0.016 だからです。 検定の欠陥ではなく、独立な暦が6つしかないという事実が、そのまま p 値の刻みとして表に出ている。

（なお主検定〈実データ vs 生成器〉では割り当てが 8008 通りあるので、 刻みは 0.0001 で問題になりません。同じ 6 ブロック制約が、設計によって 「p の粗さ」と「検出力の低さ」という別の顔で出るということです。）

6. たくさん検定するとどうなるか — 多重比較

何に困っているか

16 統計量 × 8 生成器 = 128 セルあります。各セルを 5% 水準で見ると、 差が1つも無くても、期待値として約 6 セルが「有意」になります（128 × 0.05 = 6.4）。

Benjamini–Hochberg 法

128 個の p 値を小さい順に並べ、i 番目の p 値に対して p(i) × 128 / i を計算し、後ろから最小値を取っていく。 これが q 値（FDR、偽発見率）です。

意味は「有意と判定したもののうち、間違いが平均で何割か」。 q < 0.05 なら、拾ったものの 5% 程度が誤りという水準です。

補正が要らない場合もある

「この統計量は全 8 生成器を落とせる」という主張には、多重比較の補正は要りません。

理由：この主張が成り立つには 8 個すべてが有意でなければなりません。 たくさん試して1つでも当たれば良い、という構造ではなく、全部当たれという構造です。 これは 交差–合併検定 と呼ばれ、補正なしでもともと水準を超えません （要求が厳しい側なので、むしろ保守的）。

補正が要るのは「どこかに有意差がある」を探す側だけ。 「全部に有意差がある」を要求する側は、もともと安全側にいます。

7. 周辺分布と同時分布 — energy distance

何に困っているか

16 個の統計量を1つずつ比べて、全部「差なし」だったとします。それで安心してよいか。

いけません。1つずつ見れば合っているのに、組み合わせが現実とまったく違うことがあるからです。

直感的な例

身長と体重を考えます。ある集団 A と B で、身長の分布は同じ、体重の分布も同じ。 それでも A では背が高い人ほど重く、B では背が高い人ほど軽いかもしれません。

1変数ずつ見るかぎり（＝周辺分布）差はゼロ。 2変数の組として見て（＝同時分布）初めて差が出ます。

定義

energy distance は、多次元のまま2つの集まりを比べる指標です。 各点を 16 次元のベクトル（16 統計量の値を並べたもの）と見て、点どうしの距離だけを使います。

E = 2·（A と B の間の平均距離） − （A 内の平均距離） − （B 内の平均距離）

読み方は素直です。「よそ者との距離」が「身内どうしの距離」より大きければ、 2 つの集まりは離れている。同じ分布から来ているなら、この差は 0 になります。

この研究での使われ方

16 個の周辺分布を個別に見る層（診断層）とは別に、 16 次元ベクトル全体を1つの検定にかける層（総合層）を置いています。

結果として、energy 検定は 8 生成器すべてを落とします。個別の統計量では素通りする GJR や EGARCH も含めてです。個々の性質は合っていても、16 個の組み合わせ方が現実と違う。

ただし個別の KS も残してあります。総合スコアだけでは何が壊れているかが分からないからです。

8. 交絡と ablation — 「なぜそうなったか」を言うために

何に困っているか

「実データ vs GJR-GARCH」で leverage の KS が 0.61 出ました。 これを「GJR が非対称性を持たないから 0.61 になった」と言ってよいか。

言えません。2つを比べたとき、同時に何もかも違うからです。

0.61 に混ざっているもの
  • GJR が実データの非対称性を持たないこと　← 測りたいもの
  • ボラティリティ水準・裾の重さ・持続性の違い
  • S&P500 と日経・ハンセンなど、市場ごとの性質の違い
  • 構造変化、推定パラメータのずれ

これが 交絡 です。原因の候補が複数あって、結果だけからはどれか決められない状態。

対処 ① — 揃えられるものは揃える

v0.2 までは GARCH 族を S&P500 だけに当て、それを 6 指数すべての基準線に使っていました。 v0.3 では指数ごとにその指数自身のパラメータを当て、生成もその指数のパラメータで行います。 市場間の違いが両側に等しく入るので、差として残るものが機構に近づきます。

結論が1つ変わりました。v0.2 は「leverage だけが全8生成器を落とした」でしたが、 指数ごとに当て直すと block_bootstrap に対して判定線を越えなくなり、 全8を落とせる統計量は無くなりました。

対処 ② — 1つだけ変える（ablation）

揃えても、生成器と実データはまだ同時に何もかも違います。原因を特定するには、 比較の両側を、1つのパラメータ以外まったく同じにするしかありません。

これが ablation（除去実験、knockout）です。 基準は指数ごとに当てた GJR-t（クラスタリング・重い裾・非対称性を全部持つ）。 そこから機構を1つだけ抜きます。

「1つだけ抜く」は思ったより難しい

GJR-GARCH の分散の式はこうです（記号の意味は9章）。

σ²(t) = ω + ( α + γ·1[r<0] ) · r(t−1)² + β·σ²(t−1)

γ が「下げのときだけ余分に効く」係数、つまり非対称性です。 では γ = 0 にすればよいか。駄目です。

持続性 = α + γ/2 + β        （γ は約半分の確率で効くので γ/2）

  そのまま        0.000 + 0.223/2 + 0.876 = 0.988
  γ = 0 にすると  0.000 +     0     + 0.876 = 0.876   ← 下がってしまった

持続性が 0.988 から 0.876 に落ちます。これはクラスタリングの強さそのものなので、 非対称性と一緒にクラスタリングまで抜けてしまい、何を測ったのか分からなくなります。

正しくは γ/2 を α に足し戻す（α → α + γ/2、γ → 0）。こうすると

  γ/2 を α へ    0.1115 +     0     + 0.876 = 0.988   ← 持続性そのまま

r² に掛かる係数の期待値も、持続性も、無条件分散も変わりません。 変わるのは「符号への依存」だけです。これが正しい ablation です。

結果

excess_kurtosis0.250.370.65

ここで初めて機構に帰属できます。leverage は、この controlled ablation では 非対称性の除去に選択的に反応し（0.68、次点 0.27）、裾の除去には顕著な反応を示しません（0.06）。

（「p = 0.53 だから影響ゼロ」とは言いません。非棄却は影響が無いことの証明ではないからです。 言えるのは「この標本規模で検出できるほどの反応は無く、KS も 0.06 と小さい」まで。 識別の特異性を示す材料としては、それで十分です。）

ただし leverage はクラスタリングの除去にも 0.78 で反応します。 純粋な非対称性の検出器ではありません。

この設計のもう1つの利点

ablation には依存の問題がありません。両側とも独立な生成器の実行なので、 窓の重なりも指数間の相関も無い。5章の 6 ブロック制約が掛かりません。 標準の置換検定がそのまま厳密に使えます。

そして限界

言えるのは「GJR-t という族の中で、その機構を抜いたことに気づくか」までです。 現実の非対称性が GJR の形をしている保証はありません。 実データとの比較を置き換えるものではなく、そちらの解釈を可能にするものです。

副産物として、交絡の直接証拠が出ました。gain_loss_asymmetry と drift は、実データ vs 生成器では 6 生成器ずつ落とすのに、 3つの機構のどれを抜いても 0.06 しか動きません。

つまりこの2つが生成器行列で出していた分離は、機構の欠落ではない何かを拾っています。 「生成器行列の数字を『その機構を検出した』と読んではいけない」ことの、数字による証明です。

9. 付録：GARCH 族の式

基本の考え方

リターンを「その日の変動の大きさ × ランダムな向き」に分解します。

r(t) = σ(t) · ε(t) σ(t) はその日の変動の大きさ（ボラティリティ）、 ε(t) は平均0・分散1のランダムな数

GARCH の主張は「σ(t) は一定ではなく、昨日の動きに応じて変わる」です。

GARCH(1,1)

σ²(t) = ω + α·r(t−1)² + β·σ²(t−1)
記号意味S&P500 での推定値
ω底上げ（下限になる分散）0.017
α昨日大きく動いたら、今日の分散をどれだけ上げるか0.116
β昨日の分散をどれだけ引きずるか0.863

α + β を 持続性 と呼びます。1 に近いほど、 一度上がった変動が長く続く。ここでは 0.979、つまり非常に長く尾を引きます。 これがボラティリティ・クラスタリング——荒れた日は荒れた日が続き、 穏やかな日は穏やかな日が続く、という現象です。

右辺に入るのは r(t−1)² です。2乗しているので符号が消えます。 下げても上げても、同じだけ分散が上がる。だから GARCH(1,1) は非対称性を一切持ちません。

3章の「実データは 124 窓すべてで leverage が負、GARCH は 0 のまわりに対称」は、 この一行から必然的に出てきます。実証的な発見ではなく、構造的な帰結です。

梯子の全体

生成器持っているもの持っていないもの
gaussianなし（正規乱数を独立に引くだけ）すべて
student-t重い裾時間構造
iid boot実データの値そのもの時間の並び
block boot20日以内の時間構造（実データのまま）それより長い記憶
GARCH-nクラスタリング重い裾・非対称性
GARCH-tクラスタリング＋重い裾非対称性
GJR-t＋非対称性（下げのとき係数が増える）—
EGARCH-t＋非対称性（対数分散型・別の作り方）—

これらは壊れたモデルではありません。GARCH は良いモデルです。 ここで使えるのは、何が入っていないかが分かっているからであって、出来が悪いからではありません。

GJR-GARCH と EGARCH

GJR:　σ²(t) = ω + ( α + γ·1[r(t−1)<0] ) · r(t−1)² + β·σ²(t−1) 1[·] は「条件が成り立てば 1、成り立たなければ 0」という記号。 つまり下げた日だけ γ が上乗せされる
EGARCH:　log σ²(t) = ω + β·log σ²(t−1) + α(|z| − E|z|) + γ·z z = r/σ は標準化したリターン。 γ·z の項が符号に直接反応するので、こちらでも非対称性が作れる

推定値は GJR で γ = 0.223（α = 0.000）、 EGARCH で γ = −0.169。どちらも実データどおりの強い非対称性を持ちます。

この2つは leverage を選んだ後に梯子へ足しました。 したがって統計量の選択に対して純粋に held-out（評価専用）です。

最後に — この3層をなぜ分けるのか

① 見えるのか（不変性の監査）
定義だけで決まる。ここで「不変」なら、以下の層は全部無意味です。 データも計算も要らないので、一番先にやるべきで、一番安い。

② 有限標本で区別できるのか（ablation）
理論上見えても、実際の標本規模で見破れるとは限らない。ここがその間を埋めます。

③ その判定は信用できるのか（誤り率の較正）
統計量がどれだけ良くても、採点手続きが 56% 誤答するなら結論は出せません。

この順番には意味があります。下の層で頑張っても、上の層が駄目なら回復できないからです。 不変な統計量をいくら精密に検定しても差は出ませんし、 壊れた検定でいくら良い統計量を評価しても数字は読めません。

数値はすべて sieve-bench v0.3 の invariance.json / knockout.json / separation.json / selftest.py の出力による。 実データは S&P500・日経225・FTSE100・DAX・ハンセン・EURO STOXX 50 の 2001-07-30〜2026-08-01 の日次対数リターン 36,079 点。
